# 라이더 콜 목록 좌표 전송 작업 기록

- 이슈: [#496](https://github.com/softeerbootcamp-8th/WEB-Team7-Turkey/issues/496)
- 브랜치: `feature/496-rider-call-list-geolocation`
- 범위: frontend
- 작성일: 2026-08-13

## 무엇을 만들었나

라이더 콜 목록 화면(`rider/_authed/requests`)이 지금까지 좌표 없이 `GET /api/rider/requests`를 호출해,
백엔드의 반경(bounding box) 필터·거리순 정렬이 한 번도 실제로 타지 않던 문제를 고쳤다. 백엔드 계약은
이미 좌표를 선택 파라미터로 받도록 구현돼 있었으므로(#55/#367/#60), 이번 작업은 프론트에서
`navigator.geolocation`으로 화면 진입 시 좌표를 구해 그 요청에 실어 보내는 것으로 끝났다 — 백엔드 변경 없음.

### API

해당 없음(기존 API 그대로 사용, 프론트에서 이미 있던 선택 파라미터를 채워 보내기 시작함).

### 화면

- `frontend/src/routes/rider/_authed/requests/index.tsx`: 마운트 시 좌표를 1회 조회해
  `useGetRiderDeliveryRequests`의 `latitude`/`longitude`로 전달. 좌표 조회가 끝나기 전에는
  쿼리를 `enabled: false`로 막아 "좌표 없이 한 번, 도착 후 다시 한 번" 이중 호출을 피함.
  좌표를 못 구했을 때는 비차단 안내 배너(정보 아이콘 클릭으로 상세 안내 펼침 + "다시 시도"
  버튼)를 목록 위에 띄운다(아래 결정 3 참고).
- `frontend/src/routes/rider/_authed/requests/-requestList.ts`: `requestRiderPosition` 추가 —
  `navigator.geolocation.getCurrentPosition`을 Promise로 감싸고, 성공/실패/미지원 모든 경우에
  절대 reject하지 않고 좌표(+실패 사유)로 resolve한다(백엔드가 좌표 없는 요청을 이미 정상
  처리하므로 이 경로를 예외로 만들 이유가 없음). `getPositionUnavailableSummary`/
  `getPositionUnavailableGuidance`로 안내 문구를 만든다. `formatDistance`에 커스텀 폴백 문자열
  인자를 추가.
- `frontend/src/routes/rider/_authed/requests/-components/RequestCard.tsx`: 픽업 거리 칸의 폴백
  문구를 범용 "거리 정보 없음"에서 "내 위치 정보 없음"으로 교체(도착 거리 칸은 원래 문구 유지).

## 사람이 고른 선택

### 1. 좌표를 어떻게 얻을 것인가

- **물었던 것**: 이 저장소의 라이더 앱은 Capacitor 기반 안드로이드 네이티브 앱이고, 기존 위치 전송
  (`useLocationSender`)은 브라우저 Geolocation이 아니라 커스텀 네이티브 플러그인(`RiderLocationPlugin`)을
  거친다. 그 플러그인은 `BUSY` 상태만 허용하도록 의도적으로 막혀 있어 콜 목록(AVAILABLE) 화면에는
  재사용할 수 없다. 그래서 좌표를 어떻게 구할지가 겉보기와 달리 자명하지 않았다.
- **선택지**:
  - (A) `navigator.geolocation` 직접 사용 — 신규 라이브러리 없음, 이슈 본문이 제안한 방식과 일치.
    단 Capacitor WebView가 안드로이드 매니페스트 위치 권한을 이 브라우저 API에 실제로 넘겨주는지는
    실기기 확인이 필요(이 세션에는 안드로이드 에뮬레이터/실기기 도구가 없어 코드 리딩만으로는
    100% 장담 못함).
  - (B) 기존 `RiderLocationPlugin`에 `getCurrentPosition` 1회성 메서드 추가 — 가장 안정적이지만
    안드로이드 네이티브 Java 코드 작업 + Android 빌드 검증이 필요해 범위가 크게 늘어남.
  - (C) `@capacitor/geolocation` 공식 플러그인 추가 — 크로스플랫폼 표준이지만 신규 라이브러리라
    CLAUDE.md 규칙상 별도 확인이 필요하고, 기존 커스텀 플러그인과 위치 권한 요청 통로가 두 개로 나뉨.
- **고른 것**: (A)
- **근거**: 신규 라이브러리도 없고 네이티브 코드 작업도 없어 범위가 가장 작다. (A)가 실기기에서
  실패하더라도 아래 폴백(좌표 없이 전체 반환) 경로를 타게 될 뿐이라 지금 상태(좌표를 아예 안 보내는
  상태)보다 나빠지지 않는다는 점에서 리스크가 낮다고 판단해 사람이 확정.
- **영향**: 실기기 검증은 이번 작업 범위 밖으로 남았다(아래 "검증하지 못한 것" 참고). WebView가
  권한을 못 넘겨주는 것으로 확인되면 그때 (B)/(C)를 다시 검토한다.

### 2. 좌표 조회 실패(권한 거부·타임아웃·GPS 없음) 시 폴백

- **물었던 것**: 실패 시 에러를 보여주고 재시도를 유도할지, 좌표 없이 기존과 동일하게 전체 목록을
  반환할지.
- **선택지**:
  - (A) 좌표 없이 전체 반환 — 라이더가 콜을 아예 못 보는 상황을 막음. 백엔드가 이미 이 경로를
    "반경 필터 생략 + REQUESTED_AT 정렬 대체"로 정상 처리하므로 새 예외 상태가 아님.
  - (B) 에러 화면 + 재시도 유도 — 위치 기반 정렬이 이 화면의 핵심 가치라는 전제하에 좌표 없는
    상태를 허용하지 않음.
- **고른 것**: (A)
- **근거**: 대화 중 "배차 수락 직후 BUSY 위치 전송이 이미 있는데 부자연스럽지 않냐"는 질문이
  나왔으나 확인 결과, 콜 목록의 1회성 좌표 조회와 BUSY 위치 전송(`RiderLocationPlugin`)은 완전히
  독립된 권한 요청 경로다 — BUSY 진입 시 그 시점에 다시 권한을 요청하므로, 콜 목록에서 권한을
  거부해도 배차 수락 후 위치 전송이 자동으로 막히지 않는다. 따라서 (A)를 골라도 배송 추적이
  새로 깨지는 게 아니라고 판단해 사람이 확정.
- **영향**: 없음(기존 폴백 동작 그대로 유지, 프론트만 이 상태에 도달하는 경로가 하나 늘었다).

### 3. 좌표를 못 구했을 때 사용자에게 알릴지

- **물었던 것**: 처음엔 "일부러 하지 않은 것"으로 빼뒀는데, 사람이 직접 실제 화면으로 테스트하며
  "라이더가 왜 정렬이 안 되는지 알 방법이 없다, 안내가 있어야 하지 않냐"고 다시 문제 제기함.
- **선택지**:
  - (A) 계속 조용히 폴백 — 화면은 안 막지만 라이더가 원인을 전혀 모름.
  - (B) 비차단 안내 배너 추가 — 목록은 그대로 보여주되, 위에 짧은 안내 + "다시 시도" 버튼.
- **고른 것**: (B)
- **근거**: 다음 주 배포 환경에서 비개발자 라이더가 쓸 텐데, 위치 권한을 "이번만 허용"으로
  누르거나 시스템 설정에서 위치가 꺼져 있는 경우 등, 실패 원인을 스스로 알아챌 방법이 없다고
  판단(사람 확인).
- **영향**: 안내 문구를 만드는 과정에서 세 가지가 더 드러나 반영함(상세 대화 참고):
  1. **라이더 앱은 Capacitor WebView라 주소창이 없다** — "브라우저 주소창에서 권한을 허용하라"는
     문구는 실제 배포 환경(안드로이드 앱)에는 적용되지 않는다. `Capacitor.getPlatform()`으로
     분기해 안드로이드에서는 "휴대폰 설정 → 앱 → 권한"/"휴대폰 설정 → 위치"로 안내.
  2. **`GeolocationPositionError.code`로 원인을 추정하되 단정하지 않는다** — 실측 결과
     `PERMISSION_DENIED`(code 1)가 앱 권한 거부뿐 아니라 시스템 위치 서비스 전체 꺼짐까지 같은
     코드로 돌아오는 경우가 실제로 있어("허용되지 않았다"는 표현이 이 경우엔 부정확), 기본
     요약 문구는 원인을 특정하지 않는 중립 표현("위치 정보를 가져오지 못했어요")으로 두고,
     정보 아이콘을 눌렀을 때만 "권한·시스템 설정 둘 다 확인해 달라"는 상세 안내를 보여준다.
     `TIMEOUT`(code 3)만은 코드가 가리키는 뜻이 실제로 신뢰할 수 있어 그대로 구체적으로 쓴다.
  3. **"기기의 위치 서비스"보다 실제 화면 경로**("설정 → 위치")**로 짚어주는 게 낫다** — 안드로이드
     대부분 기기의 설정 화면에 "위치 서비스"라는 이름이 그대로 없고 "위치"로만 노출되는 경우가
     많아, 실제 내비게이션 경로 그대로 안내 문구를 다시 씀.
  4. **아이콘 요소 자체는 새 라이브러리(툴팁/팝오버) 없이 구현** — `src/components/ui/`에 아직
     아무 컴포넌트도 없어서, `useState` 토글 + 네이티브 `title` 속성(데스크톱 hover용)만으로
     펼침/접힘을 구현.

## 스스로 판단한 것

- **좌표 조회는 마운트 시 1회만, "새로고침" 버튼은 재사용**: 매 새로고침마다 GPS를 다시 잡으면
  체감 속도가 나빠지고, 콜 목록을 보는 짧은 시간 동안 라이더 위치가 크게 바뀔 가능성도 낮다고
  봐서 재조회는 화면 재진입 시로 한정했다. 실측(javascript_tool로 `getCurrentPosition` 호출
  카운트 확인)으로 새로고침 클릭 시 재호출되지 않음을 확인함.
- **`enabled: position.status === 'resolved'`로 쿼리를 지연**: 좌표 없이 먼저 쐈다가 좌표 도착 후
  다시 요청하는 이중 호출 대신, 좌표 조회(성공이든 실패든)가 끝난 뒤 한 번만 요청하도록 함 —
  목록이 "일단 전체로 떴다가 갑자기 좁혀지는" 깜빡임을 피하기 위함.
- **`getCurrentPosition` 옵션**: `enableHighAccuracy: false`(반경 필터 목적상 고정밀 불필요,
  응답 속도 우선), `timeout: 5000`, `maximumAge: 60000`. 문서화된 값은 아니고 상식적인 기본값.

## 일부러 하지 않은 것

- **배차 수락 후 BUSY 위치 전송 실패를 사용자에게 알리는 것**: 대화 중 발견한 기존 갭(권한 거부 시
  `useLocationSender`가 `console.error`만 남기고 아무에게도 알리지 않음)이지만, #496의 범위(콜
  목록 좌표 전송)와 무관한 별도 설계 주제라 이번에 손대지 않았다. — 후속: 미등록(이슈 없음, 아래
  CLAUDE.md에 한 줄만 남김).
- **콜 목록 페이지네이션(다음 페이지)·요금/배송거리 필터·정렬 방향 UI**: 수동 검증 중 발견 —
  백엔드(#60)는 이미 다 구현·테스트돼 있으나 프론트가 전혀 소비하지 않는다. #496과 무관한 별도
  화면 기능이라 이번에 손대지 않고 이슈로 분리함(아래 "새로 생긴 미결 사항" 참고).

수동 브라우저 검증(로컬 백엔드 local 프로파일 + `pnpm dev`):

- 사람이 **본인 실제 브라우저**(이 세션이 아닌, 로컬 Mac의 실제 Chrome/Safari)로 `localhost:5173`에

  기준(강남대로62길 근처)으로 배차 반경 1/3/5/10km 단계별 건수 변화, "픽업"·"도착" 거리 필드가
  서로 다른 값(라이더→픽업 vs 픽업→도착지)임을 실측 확인.

  나가고, 반경 안/밖 콜이 정확히 갈리며 거리순 정렬됨을 확인(서울시청·강남역·2/6/8km 지점에
  분산 시딩한 테스트 데이터로 검증).
- 위치 조회 실패(권한 거부) 시: 좌표 없이 요청 → 전체 목록(반경 필터 생략) 반환, 안내 배너
  노출("위치 정보를 가져오지 못했어요." 등 사유별 문구), "다시 시도" 클릭 시 좌표 재조회 →
  성공하면 배너가 사라지고 목록이 반경 필터링된 결과로 갱신됨을 확인.
- "새로 고침" 버튼 클릭 시 `getCurrentPosition` 재호출되지 않음(호출 카운터로 확인) — 좌표는
  화면 재진입 시에만 다시 조회됨.
- 안내 배너의 정보 아이콘 클릭 시 상세 안내가 펼쳐지고, 다시 클릭하면 접힘을 확인.
- 최초 배너 구현에서 `text-body-sm`(이 프로젝트 타이포그래피 스케일에 없는 값)을 써서 문단 간
  글자 크기가 달라 보이는 문제를 사람이 스크린샷으로 지적 — 실존 토큰(`text-body-md`)으로 교체.

로컬 검증 과정에서 배차 대기 타임아웃(`DeliveryTimeoutService.WAITING_TIMEOUT`, 5분)이 반복
시딩을 번거롭게 해서 **로컬에서만 60분으로 임시 연장**했다가, 검증이 끝난 뒤 5분으로 되돌리고
로컬 개발 DB도 `backend/scripts/reset-and-seed-local.sql`로 원래 시딩 데이터로 리셋했다(임시로
추가한 테스트 계정 c7~c9, 테스트 배송요청 전부 제거). 이 되돌림은 코드 diff에는 남지 않는다
(원상 복구).

### 검증하지 못한 것

- **실제 안드로이드 기기/에뮬레이터에서 Capacitor WebView가 `navigator.geolocation` 권한 프롬프트를
  정상적으로 띄우고 좌표를 반환하는지**는 이 세션에 안드로이드 에뮬레이터 도구가 없어 검증하지
  못했다. 로컬 웹 브라우저(in-app browser)에서 `navigator.geolocation.getCurrentPosition`을
  모킹해 프론트 로직(쿼리 파라미터 전달, 새로고침 시 재사용, 폴백)만 검증했다. 실기기에서 실패하는
  경우에도 이미 확인된 폴백(좌표 없이 전체 반환) 경로를 타므로 회귀는 아니다.
- 브라우저 E2E(Playwright)는 이 저장소에 러너가 없어(사람 확인 없이 신규 도입 안 함) 수행하지 않았다.
