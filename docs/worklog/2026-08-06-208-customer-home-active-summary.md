# 고객 홈 진행 중 배송 요약 작업 기록

- 이슈: [#208](https://github.com/softeerbootcamp-8th/WEB-Team7-Turkey/issues/208)

- 범위: frontend
- 작성일: 2026-08-06

## 무엇을 만들었나

정적이던 고객 홈(`customer/_authed/index.tsx`)에 진행 중 배송 요약을 붙였다. #100 이 만든
`GET /api/customer/deliveries/active`(Orval 훅 `useGetCustomerActiveDelivery`)를 소비한다.

- 진행 중 배송이 **있으면**: "퀵 부르기" 버튼을 없애고, 상태 + 출발지→도착지 + 물품 종류·접수 시각
  요약 카드를 보여준다. 카드를 누르면 추적 화면(`/customer/deliveries/$deliveryId/tracking`)으로 간다.
  (물품 종류는 #100 후속(#408)에서 `ActiveDeliveryResponse.itemType` 이 추가돼 표시 가능해졌고,
  접수 시각은 `requestedAt`(기존 필드)을 `formatDeliveryRequestedAt` 로 포맷해 보여준다.)
- **없으면**: "퀵 부르기"를 주 동작으로 둔다.
- 조회 **로딩/실패**는 요약 영역에만 표시하고 홈 전체를 오류 화면으로 만들지 않는다. 실패 시에는
  퀵 부르기를 fallback 으로 열어 둔다(진행 중이면 생성은 서버가 409 로 막는다).

배송 내역(이용기록) 목록 진입은 홈에서 빼고 설정 화면(`account/settings.tsx`)에 "배송 내역"
항목으로 옮겼다(고객 전용). 홈에서 목록으로 가던 "현재 배송 상태 보기" 버튼은 제거했다.

### 화면

| 라우트 | 변경 | 소비 훅 |
|---|---|---|
| `customer/_authed/index.tsx` | 진행 중 배송 요약 카드 / 퀵부르기 분기 | `useGetCustomerActiveDelivery` |
| `account/settings.tsx` | 고객 전용 "배송 내역" 행 추가(→ `/customer/deliveries`) | 없음(Link) |

상태 문구는 공용 `getCustomerDeliveryStatusLabel`(#204)을 재사용했다.

### 스키마 변경

해당 없음(프론트).

## 사람이 고른 선택

### 1. 홈에서 진행 중 배송이 있을 때 "퀵 부르기" 처리

- **물었던 것**: 이슈는 "퀵 부르기 비활성 처리 및 안내"라고 적었다.
- **고른 것**: **버튼을 아예 없앤다**(비활성이 아니라 제거) + 요약 카드만 노출.
- **근거**: 사람 확인(2026-08-06, "콜 부르기 버튼도 없애고"). 진행 중이 명확하면 비활성 버튼을
  남기는 것보다 요약 카드로 대체하는 게 홈 의도에 맞다.
- **영향**: 이슈 문구(비활성)와 다르게 구현했다. 완료 조건 판정 시 참고.

### 2. 배송 내역(목록) 진입 위치

- **물었던 것**: 홈 재구성으로 "현재 배송 상태 보기"(→목록) 버튼이 사라지는데 목록을 어디서 들어가나.
- **선택지**:
  - (A) 설정 화면으로 이동 — 홈에서 제거, 설정에 "배송 내역" 추가 / 설정 파일(#388)을 건드림
  - (B) 이번 PR 보류 — 목록이 UI 에서 잠깐 진입 불가
  - (C) 홈에 유지
- **고른 것**: (A)
- **근거**: 사람 확인(2026-08-06, 최초 요청 유지). 목록이 UI 에서 붕 뜨는 구간을 만들지 않는다.
- **영향**: 설정은 역할 무관 화면이라 `session.role === 'CUSTOMER'` 일 때만 이 항목을 노출한다
  (라이더가 눌러도 customer 가드가 막지만 애초에 보이지 않게).

## 스스로 판단한 것

- **Orval 재생성이 `getDeliveryRequests` → `getRiderDeliveryRequests` 리네임을 딸려 왔다** —
  #367 에서 백엔드 operationId 가 이미 바뀌었는데 커밋된 생성물이 stale 였다(`useGetDeliveryRequests`).
  생성물은 손으로 수정 금지라 부분만 되돌릴 수 없어 **전체 재생성을 커밋**하고, 유일한 소비처
  `rider/_authed/requests/index.tsx` 의 import·호출명을 기계적으로 맞췄다(`useGetRiderDeliveryRequests`).
  파라미터(`radiusMeters`, `sort`)는 이름만 바뀌고 형태는 그대로라 로직 변경은 없다. 이걸 안 고치면
  프론트 빌드가 깨진다(CI 가 프론트 빌드를 돌리지 않아 dev 에 stale 로 남아 있던 문제).
- **로딩 중에는 퀵부르기·요약 둘 다 감추고 안내 문구만 둔다** — 진행 중 여부를 알기 전에 어느 쪽을
  보여줄지 정할 수 없어서다. 실패 시에는 퀵부르기를 fallback 으로 연다(이슈 "나머지 버튼은 계속 동작").
- **요약 카드는 BEM(`.customer-home__summary`) + lucide 로 만들었다** — 이 화면이 저장소에서
  유일하게 lucide + BEM 을 쓰는 곳이라(#208 비고, #197 범위 밖) 기존 스타일 체계를 유지했다.
- **응답 `data == null` 로 "진행 중 없음"을 판정한다** — #100 이 200 + data:null 로 빈 결과를 준다.

## 일부러 하지 않은 것

- **브라우저 E2E**: 이 저장소 프론트에는 테스트 러너가 없다(`CLAUDE.md`) — 이유: 새 의존성은 사람
  확인 필요 — 후속: 없음. 대신 `pnpm typecheck`/`build`/`test`(단위) 로 검증했다.
- **진행 중/없음 두 상태의 실제 브라우저 확인**: 세션·주문 픽스처가 필요해 이 세션에서 수행하지
  않았다 — 후속: 사람이 로그인해 두 경우를 눈으로 확인.
- **배송 일러스트 자산**: 기존 `TODO` 플레이스홀더를 그대로 뒀다(#208 별건, 이미지 자산 미정).
