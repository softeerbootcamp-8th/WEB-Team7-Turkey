# 역할별 세션 병렬 조회 쿠키 삭제 임시 완화 작업 기록

- 이슈: [#288](https://github.com/softeerbootcamp-8th/WEB-Team7-Turkey/issues/288)
- 브랜치: `fix/288-session-role-hint`
- 범위: frontend

## 문제

역할을 모르는 프론트 가드가 고객·라이더 세션 API를 병렬 호출했다. 유효한 고객 세션으로 라이더 API를
호출하거나 그 반대로 호출하면 역할 불일치 401이 발생하고, 백엔드는 공용 `SESSION_ID` 만료 쿠키를
응답한다. 프론트 인터셉터의 리다이렉트를 우회해도 브라우저가 이 쿠키를 적용하므로 로그인이 풀렸다.

## 사람이 고른 선택

- 저장된 역할 정보가 없으면 세션 API를 호출하지 않는다.
- 고객·라이더 로그인 성공 시 역할 힌트를 별도로 저장한다.
- 이후에는 역할 힌트에 해당하는 세션 API 하나만 조회한다.

역할 힌트는 `localStorage`의 `turkey.session.role`에 `CUSTOMER` 또는 `RIDER`로 저장한다. 이 값은
조회 대상 선택용이며 인증·인가 근거가 아니다. 서버는 계속 HttpOnly 세션 쿠키로 요청을 검증한다.

## 구현

- `shared/auth/sessionRole.ts`가 역할 힌트 저장·조회·정리를 담당한다.
- 역할 힌트가 없으면 `ensureSessionInfo`는 요청 없이 `{ role: null }`을 반환한다.
- 힌트가 있으면 고객 또는 라이더 세션 API 하나만 호출한다.
- 선택한 세션 API가 401이면 역할 힌트와 두 역할의 세션 캐시를 제거한다.
- 고객 로그인 성공은 `CUSTOMER`, 라이더 로그인 성공은 `RIDER`와 응답 데이터를 세션 캐시에 저장한다.
- 정적이던 라이더 로그인 화면을 기존 Orval `useRiderLogin` 훅에 연결했다.

## 제한과 후속 작업

- HttpOnly 세션 쿠키는 프론트가 존재 여부를 읽을 수 없다. 쿠키는 유효하지만 역할 힌트가 삭제된 경우에도
  비로그인으로 보이므로 이 방식은 임시 완화다.
- 힌트가 오래됐거나 변조되면 잘못된 역할 API의 401이 유효한 쿠키를 삭제할 가능성이 남는다.
- 최종 해법은 역할 무관 `GET /api/session`을 추가하고 응답 역할을 정본으로 사용하는 것이다.
- 로그아웃 화면이 구현될 때는 성공·실패와 관계없이 역할 힌트와 쿼리 캐시를 함께 정리해야 한다.

## 테스트

- 역할 힌트 없음 → 세션 API 0건
- `CUSTOMER` → 고객 API만 호출
- `RIDER` → 라이더 API만 호출
- 선택한 API의 401 → 역할 힌트·캐시 제거
- 5xx·네트워크 오류 → 로그아웃으로 오해하지 않고 오류 유지
- 고객·라이더 로그인 응답 → 역할 힌트와 해당 세션 캐시 저장
- 고객·라이더 로그인 필수값 및 오류 문구 검증
