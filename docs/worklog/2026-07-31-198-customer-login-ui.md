# 고객 로그인 화면 API 연동 작업 기록

- 이슈: #198 `[FE-CUS-LOGIN-001] 고객 로그인 화면 API 연동`
- 브랜치: `feature/198-customer-login`
- 범위: `frontend`
- 작업일: 2026-07-31

## 구현 내용

- 고객 로그인 화면을 React 제어 컴포넌트 방식의 폼으로 구현했다.
- 로그인 ID와 비밀번호 필수값을 요청 전에 검증하고, 각 입력 아래에 오류를 표시한다.
- 생성된 `useCustomerLogin` 훅으로 고객 로그인 API를 호출한다.
- 요청 중에는 로그인 버튼을 비활성화해 중복 제출을 막는다.
- 로그인 성공 시 기존 세션 쿼리 캐시를 제거한 뒤 로그인 응답으로 고객 세션 캐시를 확정하고, 원래 목적지가 있으면 해당 경로로 이동하며 없으면 `/customer`로 이동한다.
- 401 로그인 실패와 네트워크·서버 오류를 구분해 `role="alert"`로 안내한다.
- 회원가입 버튼을 `/customer/signup`에, 뒤로 가기 버튼을 루트 화면에 연결했다.
- 이미 로그인한 사용자가 접근하면 비인증 가드 정책에 따라 역할별 홈으로 이동한다.

## 사용 API

| 메서드 | 경로 | 용도 | 오류 처리 |
| --- | --- | --- | --- |
| POST | `/api/customer/login` | 고객 로그인 및 서버 세션 쿠키 생성 | 401은 계정 정보를 추측하지 않는 공통 로그인 실패 문구, 네트워크·서버 오류는 별도 문구 표시 |

인증 정보는 기존 Axios의 `withCredentials: true` 설정을 사용하며 로컬 스토리지에 저장하지 않는다.

## 결정 사항

### 요구사항으로 확정된 선택

- 새 의존성을 추가하지 않고 React 상태를 사용하는 제어 컴포넌트로 구현했다.
- 로그인 실패 시 서버 응답의 세부 원인을 노출하지 않고 동일한 문구를 사용한다.

### 구현 중 판단한 선택

- 성공 후 익명 또는 실패 상태로 남아 있을 수 있는 세션 쿼리를 제거하고 로그인 응답을 고객 세션 캐시에 저장했다. 역할을 이미 아는 시점에 고객·라이더 세션 API를 다시 병렬 호출하면 라이더 역할 불일치 401의 만료 쿠키가 방금 발급된 공용 `SESSION_ID`를 지울 수 있기 때문이다.
- 검증된 내부 `redirect` 경로가 있으면 해당 경로를 우선하고, 없을 때만 `/customer`로 이동한다.
- API 계약과 생성 훅이 이미 존재하므로 Orval 코드는 다시 생성하지 않았다.
