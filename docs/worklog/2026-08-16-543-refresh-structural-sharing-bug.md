## 스스로 판단한 것

- **원인 진단**: react-query가 기본으로 켜두는 structural sharing(새 응답이 이전 응답과
  내용이 완전히 같으면 `data` 참조를 재사용) 때문에, `data`/`error` 객체 참조에 의존한
  `useEffect`가 "내용은 같지만 실제로는 새 fetch가 일어난" 순간을 놓쳤다. `refreshList()`가
  미리 비워둔 상태(`items=[]`, `hasLoadedOnce=false`)가 그 이펙트로 다시 채워지지 않고
  그대로 남아 두 증상(빈 안내 문구 소실, 데이터 있는데 0건 표시)이 났다.
- **`data`/`error` 대신 `dataUpdatedAt`/`errorUpdatedAt` 사용**: 이 값들은 응답 내용이 같아도
  fetch가 끝날 때마다 새 타임스탬프로 갱신되므로, structural sharing과 무관하게 "fetch
  완료"를 정확히 신호한다. react-query 표준 대응 패턴이다.

## 일부러 하지 않은 것

- **자동화된 회귀 테스트**: 이 버그는 컴포넌트 렌더링 + react-query 캐시 동작이 얽힌
  문제라, 이 화면에 아직 없는 컴포넌트 렌더 테스트 인프라(React Testing Library 등)가
  있어야 제대로 재현할 수 있다. 이번엔 로컬 수동 검증(0건 상태 새로고침, 데이터 있는
  상태에서 같은 조건 새로고침)으로만 확인했다 — 후속으로 컴포넌트 테스트 인프라를 도입할지는
  별도 논의가 필요하다(미등록).
