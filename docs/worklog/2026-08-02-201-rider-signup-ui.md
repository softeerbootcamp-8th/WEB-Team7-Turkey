# 라이더 회원가입 화면 API 연동 작업 기록

- 작성일: 2026-08-02

## 무엇을 만들었나

정적 라이더 회원가입 폼을 제어 컴포넌트로 전환하고 아이디 중복 확인, 휴대전화 인증번호 발송·확인,
라이더 회원가입 API를 연결했다. 입력 변경 시 이전 중복 확인과 휴대전화 인증 결과를 무효화하며,
필드 오류·서버 오류·네트워크 오류·요청 중 중복 제출 방지를 화면에 표시한다.

### API

| 메서드 | 경로 | 설명 | 주요 실패 응답 |
|---|---|---|---|
| GET | `/api/login-ids/availability` | 로그인 ID 사용 가능 여부 확인 | 400 입력 오류 |
| POST | `/api/phone-verifications` | 가입용 휴대전화 인증번호 발송 | 409 가입 번호, 429 재전송 제한, 502 발송 실패 |
| POST | `/api/phone-verifications/confirm` | 인증번호 확인 및 일회성 토큰 발급 | 400 불일치, 404 만료·이력 없음, 429 시도 초과 |
| POST | `/api/rider/signup` | 인증 토큰을 포함한 라이더 회원가입 | 400 입력·인증·약관 오류, 409 아이디·전화번호 중복 |

### 화면

`/rider/signup`에서 생성된 Orval 훅을 소비한다. 휴대전화 인증은 회원가입 폼 안에서 진행하며,
가입 성공 시 `/rider/login`으로 이동한다. 가입 직후 초기 운행 상태가 `UNAVAILABLE`임을 안내한다.

### 스키마 변경

해당 없음.

## 스스로 판단한 것

- **차량 정보 제외**: 생성된 `RiderSignupRequest`에는 차량 종류와 차량 번호가 없으므로 기존 정적 입력을 제거했다. 차량 정보를 회원가입에서 받아야 한다면 백엔드 요청 스키마 변경을 별도 이슈로 다룬다.
- **휴대전화 인증 구성**: #199에서 선택한 회원가입 폼 내부 인증 방식을 그대로 적용해 화면 간 토큰 전달을 만들지 않았다.
- **서버 중복 응답 우선**: 사전 중복 확인 후에도 가입 요청이 409를 반환하면 확인 상태를 무효화하고 서버 메시지를 해당 필드에 표시한다.
- **인증번호 재시작**: 확인 API의 404·429 응답은 인증 상태를 초기화하고 재발송을 안내한다.
- **local 인증번호 표시**: local 프로파일 응답에 `debugCode`가 있을 때만 화면에 표시한다.

## 일부러 하지 않은 것

- **약관 목록·동의 연결**: #72가 완료되지 않아 요청에는 빈 `agreedTermIds`를 전달한다. 활성 필수 약관이 등록된 환경에서는 서버가 가입을 거부할 수 있다. — 후속: #72
- **차량 정보 API 추가**: 현재 생성된 Orval 타입에 없는 필드를 프론트에서 임의로 전송하지 않았다. 필요하면 별도 백엔드 이슈로 요청 스키마를 확장한다.
- **별도 `auth/verify` 화면 구현**: 고객 회원가입과 동일하게 회원가입 폼 내부 인증으로 대체했다.

### 검증하지 못한 것

- 실제 백엔드를 사용한 인증번호 발송·확인과 가입 성공·중복·인증 미완료 흐름은 브라우저에서 확인하지 않았다.
