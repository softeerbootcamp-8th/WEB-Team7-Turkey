## 위키에 게시하는 법

**파일명이 곧 위키 URL**이다. `CORE-콜받기.md` → `.../wiki/CORE-콜받기`.
흐름도의 `click ... href`가 이 URL을 그대로 가리키므로 **파일명을 바꾸면 링크가 깨진다.**

```bash
git clone https://github.com/softeerbootcamp-8th/WEB-Team7-Turkey.wiki.git
cp docs/wiki/CORE-*.md WEB-Team7-Turkey.wiki/
cd WEB-Team7-Turkey.wiki && git add . && git commit -m "docs: CORE 위키 6개 추가" && git push
```

웹 UI로 만들 때는 **New Page 제목을 표의 「위키 제목」 그대로** 넣는다(공백은 GitHub이 하이픈으로 바꾼다).
제목에 대괄호를 넣으면 URL이 퍼센트 인코딩돼 링크가 불안정해지므로 쓰지 않는다.

## 페이지 구조 규칙

```
# 제목
## 한 줄 결론      ← 링크가 대체할 수 없는 유일한 정보. 반드시 있어야 한다.
📐 결정 기록(ADR)
## 💬 디스커션      ← 왜 이렇게 정했나
## 🎫 이슈          ← 무엇을 구현했나
## 📊 테스트        ← 어떻게 검증했나
## 📚 스터디        ← 그걸 고를 수 있게 된 배경 지식
```

- **본문을 쓰지 않는다.** 디스커션·이슈 본문을 복사하면 원본이 갱신될 때 위키만 낡아 정본이 흐려진다.
- **링크는 제목만 둔다.** 이 저장소 디스커션 제목은 대개 그 자체로 한 줄 설명이다.
  제목만으로 왜 여기 있는지 알 수 없는 것만 ` — 짧은 설명`을 붙인다.
- 해당 분류에 자료가 없으면 비워 두지 말고 `_아직 없음._`으로 남겨 **빠뜨린 것과 원래 없는 것을 구분**한다.

## 알려진 공백

- **세션에서 위키를 읽을 수 없다.** 저장소가 비공개라 `.wiki.git` 클론도 웹 접근도 실패한다.
  현재 링크는 **사람이 붙여넣어 준 위키 페이지 목록(28개, 2026-08-13)** 을 근거로 걸었다.
  위키에 페이지를 추가·개명하면 이 파일들이 자동으로 따라가지 않으니 직접 갱신해야 한다.
- **ADR-004(프론트엔드 디렉터리 구조)는 어느 CORE 페이지에도 걸지 않았다.** 흐름도 노드가 다루는
  주제가 아니라서다. 프론트 구조를 흐름도에 넣게 되면 그때 연결한다.
- **결제 정합성에 디스커션이 #402 하나뿐이다.** 포인트·PG 논의가 따로 있었다면 누락이다.
- **스터디가 얇다.** 학습 이슈 두 건(#258, #329)과 위키 가이드 두 개(Grafana 사용법,
  기술적 난제 정의)뿐이다. 팀 스터디 기록이 다른 곳에 있으면 추가한다.
